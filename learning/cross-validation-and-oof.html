Cross-validation and out-of-fold predictions

This is a revision note, not a session brief. It pulls together what I actually learned building a reusable validation harness on a Kaggle problem, and why every serious model I score from now on goes through it.

The short version: one train/test split gives you a number with no error bar, and you cannot tell a real improvement from noise. Cross-validation replaces that one number with a mean and a spread, and — as a side effect — hands you a prediction for every training row made by a model that never saw it. That second thing, the out-of-fold vector, turns out to be worth as much as the score.

Why one split is not enough

The reflex is train_test_split(X, y, test_size=0.2): fit on 80%, score on 20%. Two problems, and they compound.

  • You only scored 20% of your data, once, on one arbitrary cut. Change the random seed and the score moves. You have no idea by how much.
  • You have no error bar. When a new model scores 0.9140 against your baseline's 0.9115, is that a real gain or did the split happen to fall kindly? A single split cannot answer this, so you end up chasing noise up the leaderboard.

The whole discipline exists to stop that.

K-fold: rotate the held-out slice

Split the data into k equal parts (folds). Train on k−1 of them, validate on the one left out, and rotate so each fold is the validation set exactly once. With k = 5 you fit five models; every row is validated once, by a model that never trained on it. You get five scores instead of one — so you get a mean and a standard deviation.

Stratified k-fold does one extra thing for free: it keeps each fold's positive rate equal to the whole set's. On a 71/29 problem that removes a source of fold-to-fold variance you don't want — the folds differ because of the model, not because one happened to draw more positives.

from sklearn.model_selection import StratifiedKFold
skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
for tr, va in skf.split(X, y):
    ...   # tr, va are arrays of integer ROW POSITIONS, not data

The trap that cost me the most time: skf.split yields index arrays, not the rows themselves. tr is something like [0, 1, 2, 5, 6, ...]. To get the data you index with them: X.iloc[tr]. Passing tr straight into .fit trains the model on a list of integers, which is nonsense.

The out-of-fold (OOF) vector

Here is the part I underrated. Because every row is validated exactly once, you can write each fold's predictions back into their original positions and build a single vector oof the length of the whole training set — where every entry was predicted by a model blind to that row.

oof = np.zeros(len(X))
for tr, va in skf.split(X, y):
    m = clone(model)                                # fresh, unfitted copy
    m.fit(X.iloc[tr], y.iloc[tr])                   # train-fold rows only
    oof[va] = m.predict_proba(X.iloc[va])[:, 1]     # honest, leak-free scores

A single train/test split cannot give you this — 20% of your rows would never get a prediction. The OOF vector is honest raw material you reuse later: it is what you feed a second-stage model when stacking (blend two models' OOF predictions to beat either alone), what you calibrate against, and what you bootstrap for a confidence interval. Throw it away and you redo all the fitting later.

Two details in that loop matter. clone(model) copies the settings but returns an unfitted model, so each fold starts clean. And predict_proba(...)[:, 1] takes the positive-class probability — not .predict(), which returns hard 0/1 labels and quietly wrecks a ranking metric like AUC (that mistake has its own note).

Two more things the same loop gives you

A free ensemble. Each fold's model can also predict the real test set; average the k predictions and you have a k-model ensemble at no extra cost:

test_pred += m.predict_proba(X_test)[:, 1] / n_folds

Leak-free preprocessing — if you build it right. Any step that learns from the data (imputing missing values with the median, scaling to unit variance) must be fit on the training fold only. The clean way is to put those steps inside the model as a pipeline and pass raw data:

pipe = make_pipeline(SimpleImputer(strategy="median"), StandardScaler(),
                     LogisticRegression(max_iter=1000))

Now clone(pipe).fit(...) re-fits the imputer and scaler on each fold's own rows. The tempting shortcut — impute the whole dataset first, then cross-validate — leaks: the median is computed using rows that later become validation rows, so the model gets a peek at data it is about to be tested on. Small for a median fill, a real bias for heavier transforms, and wrong in principle either way.

The payoff, on real numbers

On a Kaggle binary problem (screen-time addiction, ~690k rows, AUC-scored), the same harness scored two models under identical 5-fold splits:

hgb       0.95476 +/- 0.00060
logreg    0.91148 +/- 0.00081

The gradient booster beats logistic regression by 0.043 of AUC. The reason I can state that as real: the gap is roughly fifty times the combined error bars. A single split would have given me two bare numbers with no way to know whether the difference was skill or luck. And re-running the logistic model with a different shuffle gave the identical mean, 0.91148 — the estimate does not depend on where the fold boundaries happen to fall, which is exactly what a tight error bar is telling you.

Status

Closed — I can state these without looking them up:

  • One split gives a point estimate with no error bar; k-fold gives mean ± std
  • Stratified folds hold the class balance constant so fold variance reflects the model, not the draw
  • skf.split yields row-position index arrays; index the data with X.iloc[tr]
  • The OOF vector = every row predicted by a model blind to it; it is the input to stacking, calibration, and a bootstrap CI
  • Preprocessing that learns from data must live inside the pipeline so it re-fits per fold; imputing before the split leaks
