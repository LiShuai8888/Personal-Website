Meta-labeling, the triple barrier, and a look-ahead I shipped

This is a revision note, not a session brief. It covers the meta-labeling code I committed to the algo-trading repo on 2026-07-16 and 07-18, the honest result it produced, and the two things I got wrong — one in how I described the label, one in the code itself. The ROC note already carries the AUC numbers; this note is about what the model was and why its answer is quieter than it first looked.

The short version, in three sentences. Meta-labeling is a second model that decides whether to take a trade the primary strategy already chose — side from the strategy, take/skip from the model. Across all fourteen of my bar strategies it scored an out-of-fold AUC of 0.51–0.58, and that tight band is the finding, not a disappointment: it says I built one weak generic signal, not fourteen edges. And the first Sharpe uplift I reported, +3.86, was mostly an artefact of two bugs I can now name.

What meta-labeling actually is

The idea comes from López de Prado. Keep the primary strategy that decides direction — long or short — and train a separate classifier that only answers a narrower question: given that this strategy just fired, does the trade make money? The classifier never picks the side. It sits on top and decides whether the bet is worth taking, and by extension how large.

In my code the split is literal. harvest_signals replays the real strategy class over the bars and records every non-flat entry, so the signals are identical to what would trade live — no reimplemented math. Each of those entries becomes one training row: features computed causally at the entry bar, and a label for whether it won.

The point of conditioning on the primary is that the model is not asked to find trades from scratch. It only has to sort the ones already on the table into keep and discard. That is a much easier question, which is exactly why a weak AUC can still be useful — and exactly why it is easy to fool yourself about how much it added.

The label I shipped is not the triple barrier

This is the first thing I had described loosely. The label in labeling.py is fixed-horizon, not triple-barrier:

fwd_net = dirs * (close[exit_idx] / close[entry_idx] - 1) - rt_cost
label   = (fwd_net > 0)          # 1 = win, 0 = loss

Hold for horizon bars (default 10), measure the direction-adjusted return net of a round-trip cost buffer (2 × cost_bps / 1e4, so 10 bps at the default 5 bps one-way), and label the trade a win if that number clears zero. Signals without a full forward window are dropped, so there are no partial labels.

The triple barrier — first touch of a stop, a profit target, or a time limit — is a different label, and in my work it was an experiment run on 2026-08-09, not the code in this module. It matters because the two labels describe different trades: fixed-horizon holds through a stop the live engine would have honoured. When I switched the label to triple-barrier the out-of-fold AUC rose (0.562 → 0.631) while the reported Sharpe uplift collapsed (+3.86 → about +0.67). Both moved for the same reason, and the ROC note works through why that is not a contradiction.

Why ordinary K-fold leaks here

A fixed-horizon label looks horizon bars into the future, so a sample's label window [t0, t1] overlaps its neighbours'. Shuffle those rows into random folds and a training sample's future sits inside the test period — the model peeks. Standard K-fold quietly reports a number that live trading will never see.

The fix is PurgedKFold with an embargo (AFML ch. 7). Folds are contiguous blocks in t0 order — each fold is a time slice, not a random sample. Then two rules trim the training set:

  • Purge — drop any training sample whose label window overlaps the test window. In the code: keep a row only if t1 < test_t0_min (ends before) or t0 > embargo_end (starts after).
  • Embargo — additionally drop training samples for a short span after the test window, to kill serial-correlation bleed. I run embargo_days = 5 over n_splits = 6.

Every number in the note is an out-of-fold prediction: each sample scored by a model that never saw it. That is the only way the keep/discard comparison is not self-fulfilling.

The model, and why it is deliberately dull

A single gradient-boosting classifier, kept small on purpose:

HistGradientBoostingClassifier(
    max_depth=3, max_iter=200, learning_rate=0.05,
    l2_regularization=1.0, min_samples_leaf=30,
    early_stopping=True, validation_fraction=0.15,
)

Shallow trees, strong L2, a floor of 30 samples per leaf, early stopping. The comment in the code says it plainly: thin signal in daily equities, small N. The fourteen features are all causal — trailing returns over 5/10/21/63 bars, two volatility windows, RSI and its second difference, distance from the 50- and 200-day SMAs, a trend term, relative volume, ATR%. HistGradientBoosting eats NaNs natively, so the warm-up region needs no imputation.

The result that matters: 0.51–0.58 across all fourteen

Here is the open question I had been carrying since June: is the lift generic or strategy-specific? Every one of the fourteen bar strategies scored an out-of-fold AUC in the same narrow band, 0.51–0.58.

The tightness is the answer. If each strategy had its own edge, the AUCs would scatter. They don't — which smells like one weak generic forward-return signal living in the shared feature set, re-discovered fourteen times, rather than fourteen independent edges. In the weekend review I wrote it down bluntly: "AUC 0.51–0.58 across 14 strategies is the answer."

There is a clean test I have not yet run: retrain the meta-model on direction-only, strategy-agnostic features and compare. If the AUC barely drops, the thing I built is a standalone weak alpha gate and should be repositioned as one — not sold as a meta-layer that improves fourteen strategies.

The +3.86 uplift that mostly wasn't there

The first Sharpe uplift I reported for zero_cross was +3.86, and it was inflated by overlapping label windows. With a 10-bar horizon and a strategy that fires often, consecutive labels share most of their forward window, so the "independent" trades in the filtered leg are nothing of the sort. On 2026-08-09 the mean label uniqueness came out at 0.14 — roughly 59,500 samples carrying about 8,300 observations' worth of independent information. An uplift computed as if those were 59,500 clean trades is going to look far bigger than anything tradable.

The fix I still owe the code is a non-overlapping-signal de-dup in the same pass, so the reported uplift stops being an artefact. This is the same effective-sample-size problem already flagged against the confidence intervals in the ROC note.

The look-ahead I shipped

The one that stings. labeling.py:150 prices the entry at the decision bar's close:

fwd_net = dirs * (close[exit_idx] / close[entry_idx] - 1.0) - rt_cost
#                                    ^^^^^^^^^^^^^^^^
#                       entry priced at close[entry_idx] — the SAME bar the signal fired on

This is the exact look-ahead the SimulatedBroker was built to prevent: you cannot see a bar's close and also transact at it. For rsi_d2, which fires on an oversold close, it is worse than a generic bias — it hands the model the overnight bounce for free. And it contaminates everything at once: the baseline leg, the filtered leg, and the labels the AUC is scored against. Some part of that honest-looking 0.51–0.58 is this bug, not signal. The fix is to price the entry at the next bar's open; until I do, every number here has an asterisk.

Status

Closed — I can state these without looking them up:

  • Meta-labeling = primary picks the side, a second model picks take/skip/size, conditioned on the primary having fired
  • Why plain K-fold leaks on horizon labels, and what purge + embargo each remove
  • The label I shipped is fixed-horizon; the triple barrier was an experiment, not the module
  • A tight AUC band across many strategies is evidence of one shared signal, not many edges
